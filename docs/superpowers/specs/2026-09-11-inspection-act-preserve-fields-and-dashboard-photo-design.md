# Акты осмотра — сохранение полей после фото и обязательное Dashboard

Дата: 2026-09-11  
Статус: одобрено в обсуждении  
Платформы: Web + Mobile (общий ViewModel)  
Вне scope: показания топлива/пробега обеих сторон (ждём бэкенд)

## Проблема

1. После загрузки фото локально введённые топливо, пробег и комментарий
   сбрасываются: `applyAct` перезаписывает inputs из DTO, где метрики ещё
   null, если пользователь не успел сохранить их на сервер.
2. Можно подписать акт без фото приборной панели. На бэке `CanSignAsOwner` /
   `CanSignAsRenter` не требуют Dashboard; клиент тоже не блокирует.

## Цели

- После upload/delete фото сохранять текущие `fuelInput` / `mileageInput` /
  `commentInput` в Ready-состоянии.
- Перед `sign()` требовать ≥1 фото `Car` и ≥1 `Dashboard` **от текущего
  пользователя** (по `authorId` / роли); иначе показать ошибку и не вызывать API.
- Покрыть регрессионными unit-тестами ViewModel.

## Не входит в задачу

- Отдельные поля fuel/mileage владельца и арендатора (бэкенд).
- Усиление `CanSign*` на сервере (можно позже; клиент уже не даст нажать вслепую).
- Изменение UI-разметки секций фото, кроме текста ошибки.

## Решение

**Правки только в `InspectionActViewModel` (+ тесты).**

### Сохранение inputs при `applyAct`

- Перегрузка / опция: при обновлении акта из сети или после мутации
  **сохранять** предыдущие непустые локальные inputs, если новые значения из
  DTO пустые / null.
- Практическое правило:
  - если пользователь уже ввёл текст в поле — не затирать его пустым ответом;
  - если DTO вернул непустое значение (после `updateMetrics` / комментария) —
    брать серверное.
- После `uploadPhotos` использовать тот же путь (не голый `applyAct` с
  обнулением inputs).

### Обязательные фото перед подписью

- Хелпер (в Network рядом с act helpers или private в VM): у текущей роли
  есть ≥1 `Car` и ≥1 `Dashboard` среди `act.photos` с автором = текущая сторона
  (`ownerId` / `renterId`).
- В начале `sign()` / `signAsOwner` / `signAsRenter`: если нет — `error(...)`
  или `showError` с текстом вроде «Загрузите фото автомобиля и приборной
  панели», API sign не вызывать.
- Кнопка «Подписать» может оставаться видимой (как сейчас по `canSign` с API);
  отказ — через ошибку при клике (минимальный diff). Опционально позже
  ужесточить `canCurrentUserSign` на клиенте.

### Тесты

- Upload photos при заполненных fuel/mileage/comment → inputs не пустые.
- Sign без Dashboard-фото своей стороны → ошибка, mock sign не вызван.
- Sign с Car + Dashboard своей стороны → sign вызывается (существующий happy-path).

## Критерии готовности

- `:CommonViewModels` тесты зелёные.
- Ручной сценарий: ввёл пробег → загрузил фото → поля на месте → без панели
  подпись не уходит.
